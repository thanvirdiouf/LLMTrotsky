# Reviewed claim coverage and selector budget

The longer transfer study exposes a representation limit as well as selection
and conversation failures. The complete supplied passages contain secretary
count uncertainty, Eastman theoretical differences, and the scope of Blumkin
visitor identification. The finite catalogue cannot render all of those as
facts. Other details, such as the qualified disclosure inference, already have
claims but were not selected. Neither problem is a natural retrieval miss in
the controlled-source study.

A separate AI reviewer read the complete hearing/Eastman/Blumkin packets and
their existing claims without inspecting run outputs. It proposed three bounded
additions with exact anchors, speakers, dates and original packet fingerprints.
The continuing agent checked those bindings and accepted the statements. The
Blumkin compound is classified as inference, preserving confident identification
versus separately qualified disclosure; the source's confidence is not external
corroboration. Count/Apparently quotation-mark styling is removed in the canonical
paraphrases so that requested exact quotations still use the original anchors.
The original proposal remains unchanged in the ignored local archive.

The opt-in plan `config/ghost_source_plan_v4.json` appends three claims to the
original39; every original claim field, all four reviewed brief forms and all
ten source packets remain byte-value equivalent. Source text, dates, authors,
speaker roles and context boundaries do not change. The active pointer stays
v3. This is source curation, not training data or independent human validation.

The builder's optional supplement path requires a nonempty review and exact
original historical packet fingerprints. It rejects reused IDs, source/date
metadata overrides, changed anchors or speakers, unknown statuses and modern
packet substitutions. New dates/domains are inherited from the bound packet.
The existing ledger validator runs over the combined claims. This validates
bindings and schema, not historical truth or the quality of a paraphrase.

Adding the three claims without changing selector metadata produced five
preflight requests over the 5,120-token cap (maximum5,211) with recorded V21
histories. The variant therefore also opts out of proposition anchor offsets
in the selection request. Selection still receives every source word, source
block speaker/date/context and reviewed proposition ID/text/status/attribution.
Drafting and auditing retain offsets; immutable fact and exact-quote rendering
still use the full checked ledger anchors. Default v3 behavior is unchanged.

With that selector-only metadata omission, all ten final preflight selectors fit,
maximum4,711 tokens, with full source-packet JSON identical to V21. This uses
recorded histories, not a guarantee about future generated replies or later
selected draft/check inputs. The runtime still rejects over-budget requests
before inference. Earlier unsubmitted local evidence builds are preserved;
the final variant is materialized at `evaluation/ghost_chat_v4_ready/`.

Four new tests exercise original-input preservation, source/anchor/speaker
binding, new-ID and metadata boundaries, and full source retention through a
real answer pipeline while offset omission applies only to selection. All76
focused tests pass. The full349 suite retains the same two pre-existing
historical README snapshot errors. No historical locks are changed.

V24 freezes the existing two-plus-eight transfer questions with this optional
coverage/selector variant and the current experimental checker framing. It
remains ten replies, at most30 calls plus one short memory probe on the same
private free-Kaggle notebook. This compares a combined application/evidence
candidate with inspected regressions. It is not a single-component causal
ablation, fresh generalization study or representative quality score. The source
packets/questions/base controls remain fixed; the ledger, selector metadata and
checker instruction differ from V21. Review exact displayed replies and actual
inputs before considering activation; new claims are not a quality promotion.

Sources/propositions/review snapshots and generated notebooks remain ignored.
Only the builder, plan, tests and documentation are published. Training and both
experimental adapters remain unchanged.
