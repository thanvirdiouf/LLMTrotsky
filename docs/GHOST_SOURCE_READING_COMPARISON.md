# Matched factual source-reading comparison

V24/V25 show a bottleneck beyond source retrieval. The application can receive
and select the needed propositions, then discard them under its packing policy.
A factual calculation can be drafted correctly yet filtered for lacking a
historical political basis. A fixed catalogue cannot directly compose every
new numerical or close-reading answer from a complete supplied passage.

V26 compares two independent factual pipelines on five fixed questions. Both
receive identical at-most-two source packets, the same untouched pinned base,
profile,42-claim ledger and generation settings. The questions cover hearing
fields, Eastman theory/pressure, Blumkin inference scopes, report routes and
hypotheses, and the ILO numerical denominator. Existing exact question strings
and source-review checks are reused; this is a failure-focused development
comparison, not fresh validation or representative reliability measurement.

The canonical arm uses the current planner, immutable factual cards, a possible
fictional paragraph if classified mixed, and model review. The reading arm uses
`SourceReadingChat`: a neutral factual writer reads the complete source blocks
without proposition cards, then the same base audits its paragraphs with
reading-role clarification. There is no political-basis requirement for factual
arithmetic. This compares combined pipelines; routing, generation, quote checks
and audit representation differ. It does not isolate a single causal component.

The reading writer receives source dates/authors/speakers/context, the question
and explicit hypothetical assumptions. It must preserve reports, hypotheses,
predictions and qualifications, distinguish source testimony from independent
confirmation, answer supported portions and state missing evidence. It may
paraphrase and calculate from the supplied data. None of those instructions
guarantees semantic correctness; the auditor remains fallible.

Reading is bounded to one to four paragraphs and2,000 characters, without
invented links, citation markup or HTML tags. Quoted spans must occur literally
in a supplied source or current user question; source matches retain block and
speaker references. User-only matches are explicitly unverified. Occurrence
checks do not authenticate attribution, preserve omitted qualifications or
verify an event; the auditor and later source review must assess those things.
Source-context citations are application-generated and are not sentence-level
entailment proof.

Each paragraph receives a verdict. Missing judgments reject rather than approve
that paragraph; incomplete/truncated stages block. Source analysis is labelled
as a reading, and no generated claim becomes a verified claim ID or interpretation
memory. The diagnostic requires a fresh independent case and rejects conversation
history. It is not yet a replacement for the sustained-conversation engine or
an activated product route.

Every paired question resets state/history. All five canonical cases run first,
then their reading counterparts. Canonical cases use at most three calls each;
reading cases use two, so ten displayed replies require at most25 calls plus
one separate memory probe. Same private free-Kaggle notebook, no training,
adapters or paid compute. The active evidence pointer remains v3.

Four new tests exercise full-source numerical reading without a historical
basis, empty verified memory, quotation origins, rejection/missing/truncated
verdicts, independent state and exact cached replay. All81 focused ghost tests
pass. The full354 suite retains two known historical README snapshot errors;
old locks are unchanged. No original README bytes were reconstructed or hashes
rewritten to hide those errors.

CPU preflight constructs all ten cases and both stages with short synthetic
responses. Paired retrieval traces are identical, reviewer metadata keys are
withheld, and the maximum synthetic prompt is4,030 tokens under5,120. This is
not a bound on a future generated draft/check payload; the runtime checks every
actual request before inference. Expected checks and synthetic answers are not
sent to the base model as targets or training data.

After exact-version download, frozen-code replay and token reconstruction,
export only actual displayed replies and full sources for a masked comparison.
Keep model verdicts, rejected drafts, pipeline mappings and implementation traces
out of that semantic review. Report task completeness, support/certainty/roles,
necessary limits, unnecessary refusals and format failures separately. Partial
blinding is unavoidable where response labels/style reveal a method difference.
Choose later integration from those results; neither model approval nor this
small comparison establishes reliable factual synthesis.

## Verified V26 result and V27 follow-up

V26 completed as private saved version28. Frozen replay and local tokenizer
reconstruction verified ten replies,20 evaluation calls, no input rejection or
truncation, and11.32GiB peak. Four reading drafts stopped before auditing because
they contained nonliteral quotations. The one displayed reading lost hypothesis
scope and overstated source confirmation despite all-positive model verdicts.
Canonical replies also omitted requested fields, inference distinctions and the
ILO calculation. Neither pipeline establishes reliable full task completion.

An unblinded implementation review, bound to all ten displayed-response hashes,
is retained locally in ghost_smoke_v26/implementation_review.json. It distinguishes
displayed replies from hidden drafts; it is neither independent nor human review.
No source-reading promotion or active-pointer change follows these results.

V27 repeats the same five matched development questions and source packets. Only
the experimental reading writer instructions change: paraphrases without quote
marks, explicit hypothesis scope, speaker/inference subjects, and percentage
denominators. Quote validation, auditing, immutable canonical arm and limits stay
unchanged. This is a combined prompt revision, not a single-instruction ablation,
and inspected questions remain development data. All81 focused tests pass. The
run permits at most25 evaluation calls plus one memory probe on free Kaggle.
Assess whether format failures decrease separately from factual completeness and
certainty; more model approvals alone cannot justify integration or training.
